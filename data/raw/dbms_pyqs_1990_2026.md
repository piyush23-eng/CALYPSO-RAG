## Question GATE-1998-DBMS-01: DBMS - Strict 2-Phase Locking & Cascading Aborts
**Topic**: Database Management Systems / Concurrency Control & Transactions
**Question**:
Why does the Strict Two-Phase Locking (Strict 2PL) concurrency control protocol guarantee conflict serializability and completely eliminate cascading aborts (cascadelessness)?
(A) It releases read locks at the end of transaction while write locks are held until commit/abort.
(B) It requires transactions to hold all exclusive (write) locks until the transaction completes (Commit/Abort).
(C) It locks all data items before the transaction starts execution.
(D) It prevents read locks from being shared.

**Key Technical Concepts**: Strict 2PL, 2-Phase Locking (Growing/Shrinking phase), Dirty Read anomaly, Cascading Rollback / Cascading Abort, Cascadeless Schedule.

**Step-by-Step Solution & Derivation**:
- **Standard 2PL**: Guarantees conflict serializability by ensuring transactions do not acquire any lock after releasing a lock. However, standard 2PL permits dirty reads if transaction $T_1$ releases an exclusive write lock on data item $X$ before committing, allowing transaction $T_2$ to read the uncommitted modification of $X$. If $T_1$ subsequently aborts, $T_2$ must also abort, causing cascading aborts.
- **Strict 2PL Rule**:
  $$\text{All Exclusive (Write) Locks acquired by } T \text{ must be held until } T \text{ commits or aborts.}$$
- **Consequence**:
  - Since exclusive locks are held until final commit, no other transaction can read or overwrite uncommitted dirty data written by $T$.
  - Therefore, uncommitted data is never read by concurrent transactions, preventing cascading aborts (ensuring recoverability and cascadelessness).

**Correct Answer**: (B) It requires transactions to hold all exclusive (write) locks until the transaction completes (Commit/Abort).

## Question GATE-2007-DBMS-02: DBMS - Normalization to 3NF and BCNF
**Topic**: Database Management Systems / Normalization & Functional Dependencies
**Question**:
Given relation schema $R(A, B, C, D, E)$ with functional dependencies:
$F = \{ A \rightarrow BC, CD \rightarrow E, B \rightarrow D, E \rightarrow A \}$
What is the highest normal form satisfied by relation $R$?
(A) 1NF
(B) 2NF
(C) 3NF
(D) BCNF

**Key Technical Concepts**: Candidate Key calculation, Prime Attributes, Non-prime Attributes, 2NF (no partial dependency), 3NF (no transitive dependency), BCNF (LHS must be superkey).

**Step-by-Step Solution & Derivation**:
1. Find Candidate Keys via Attribute Closure:
   - Closure of $A$: $A^+ = \{A, B, C, D, E\} \implies A$ is a candidate key.
   - Since $E \rightarrow A$, closure of $E$: $E^+ = \{E, A, B, C, D\} \implies E$ is a candidate key.
   - Since $B \rightarrow D$ and $A \rightarrow BC$, closure of $BC$: $(BC)^+ = \{B, C, D, E, A\} \implies BC$ is a candidate key.
   - Since $CD \rightarrow E$, closure of $CD$: $(CD)^+ = \{C, D, E, A, B\} \implies CD$ is a candidate key.
   - All candidate keys: $\{A, E, BC, CD\}$.
2. Identify Prime and Non-Prime Attributes:
   - Prime attributes (part of any candidate key): $\{A, B, C, D, E\}$.
   - Non-prime attributes: $\emptyset$ (Every attribute in $R$ is prime!).
3. Normal Form Verification:
   - **2NF Check**: Since there are no non-prime attributes, no partial dependencies can exist. $R$ is in 2NF.
   - **3NF Check**: For every dependency $X \rightarrow Y$ in $F$:
     - $A \rightarrow BC$: $A$ is superkey $\implies$ Valid in 3NF.
     - $CD \rightarrow E$: $CD$ is superkey $\implies$ Valid in 3NF.
     - $B \rightarrow D$: $B$ is not superkey, but RHS attribute $D$ is prime $\implies$ Valid in 3NF.
     - $E \rightarrow A$: $E$ is superkey $\implies$ Valid in 3NF.
     - Since every dependency satisfies the 3NF condition (either LHS is superkey OR RHS is prime), $R$ is in 3NF!
   - **BCNF Check**:
     - For $B \rightarrow D$: $B$ is NOT a superkey of $R$.
     - Hence, $R$ violates BCNF.
- Highest Normal Form: 3NF.

**Correct Answer**: (C) 3NF

## Question GATE-2017-DBMS-03: DBMS - B+ Tree Fanout & Minimum Keys Calculation
**Topic**: Database Management Systems / B+ Tree Indexing
**Question**:
In a B+ tree of order $p = 5$ (where $p$ is the maximum number of child pointers per internal node), what is the minimum number of child pointers that a non-root internal node must contain?
(A) 2
(B) 3
(C) 4
(D) 5

**Key Technical Concepts**: B+ Tree properties, order of B+ Tree, non-root internal node occupancy, minimum/maximum child pointers: $\lceil p/2 \rceil$.

**Step-by-Step Solution & Derivation**:
- **B+ Tree Node Constraints**:
  - For a B+ tree of order $p$:
  - Root node: Minimum $2$ child pointers (if non-leaf), maximum $p$ pointers.
  - Non-root internal nodes:
    - Minimum child pointers: $\lceil p / 2 \rceil$
    - Maximum child pointers: $p$
    - Minimum keys: $\lceil p / 2 \rceil - 1$
    - Maximum keys: $p - 1$
- **Calculation for $p = 5$**:
  $$\text{Min Child Pointers} = \lceil \frac{5}{2} \rceil = \lceil 2.5 \rceil = 3$$
  $$\text{Min Keys} = 3 - 1 = 2$$

**Correct Answer**: (B) 3

## Question GATE-2023-DBMS-04: DBMS - Conflict Serializability & Precedence Graph
**Topic**: Database Management Systems / Transaction Processing
**Question**:
Consider schedule $S$ with transactions $T_1, T_2, T_3$:
$$S: R_1(X), R_2(Y), W_1(X), R_2(X), W_2(X), R_3(Y), W_3(Y)$$
Which of the following topological orders represents the equivalent serial schedule for $S$?
(A) $T_1 \rightarrow T_2 \rightarrow T_3$
(B) $T_2 \rightarrow T_1 \rightarrow T_3$
(C) $T_3 \rightarrow T_1 \rightarrow T_2$
(D) The schedule is not conflict serializable.

**Key Technical Concepts**: Conflict Serializability, Conflicting Operations ($R(X)-W(X)$, $W(X)-R(X)$, $W(X)-W(X)$ by different transactions), Precedence Graph (Serialization Graph), Topological Sort.

**Step-by-Step Solution & Derivation**:
1. Identify all conflicting pairs on shared items:
   - On item $X$:
     - $W_1(X)$ precedes $R_2(X)$ $\implies$ Edge $T_1 \rightarrow T_2$.
     - $W_1(X)$ precedes $W_2(X)$ $\implies$ Edge $T_1 \rightarrow T_2$.
     - $R_1(X)$ precedes $W_2(X)$ $\implies$ Edge $T_1 \rightarrow T_2$.
   - On item $Y$:
     - $R_2(Y)$ precedes $W_3(Y)$ $\implies$ Edge $T_2 \rightarrow T_3$.
2. Construct the Precedence Graph:
   - Vertices: $\{T_1, T_2, T_3\}$.
   - Directed Edges: $T_1 \rightarrow T_2$ and $T_2 \rightarrow T_3$.
3. Cycle Detection:
   - The graph $T_1 \rightarrow T_2 \rightarrow T_3$ contains no directed cycles (it is a Directed Acyclic Graph - DAG).
   - Hence, schedule $S$ is conflict serializable.
4. Topological Sort:
   $$\text{Equivalent Serial Schedule}: T_1 \rightarrow T_2 \rightarrow T_3$$

**Correct Answer**: (A) $T_1 \rightarrow T_2 \rightarrow T_3$
